ARGUS — MASTER HANDOFF FOR AI CODING TOOLS
Problem statement: SIH26262, Integrated AICTE Approval Workflow Automation, Compliance Monitoring and Alert Management System.
Product: ARGUS — AICTE Approval & Compliance Intelligence Platform.
Tagline: Complete Visibility. Accountable Governance.

MISSION
Build a credible, automation-first prototype that proves the complete loop: event → validate context/permissions → evaluate a configured rule → prevent duplicate action → perform a permitted action/task → record an auditable outcome → show the result in the UI. A dashboard with decorative controls is insufficient.

If source files conflict, report the conflict and propose a decision; do not silently invent a rule. Preserve the existing repository stack unless audited evidence supports a change.

P0 REQUIREMENTS
1. Synthetic application records with route profile, current stage, owner, status and due date.
2. Route-aware valid stage advancement; block invalid transitions and unauthorized actions.
3. Deficiency return requires a non-empty reason and preserves a resume stage; institution resubmission routes back for review.
4. Deadline reminders and overdue escalations evaluated by a repeatable rule cycle.
5. Idempotency: rerunning the same cycle must not create duplicate alerts/tasks for the same subject + rule + threshold window + policy version.
6. EVC eligibility queue, scheduling/assignment and report status as separate steps.
7. Evidence submission is distinct from authorized verification.
8. Document expiry warning, renewal submission and review are separate states.
9. Auditable trail with actor/system, timestamp, target, rule ID/version, reason, result and correlation/reference ID.
10. Honest demo labels: fictional records and simulated notifications; do not imply live AICTE integration.

REGULATORY AND SECURITY BOUNDARIES
Never claim ARGUS is official or AICTE-endorsed. Do not invent statutory timelines. Verify the currently applicable official handbook/circulars before loading live rules. Final regulatory scrutiny and approval/rejection decisions remain with authorized officials. AI/OCR is future advisory support only, source-linked and human-reviewed. Never use real institution/person data or commit credentials. Client-side role switching is not production security; enforce permissions server-side in the production design.
